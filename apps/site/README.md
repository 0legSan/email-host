# Сайт Email Host

Рекламный сайт для `https://emailhost.olegsan.tech` находится в отдельном Vite-приложении. Русский язык доступен на `/`, английский на `/en/`. Переключатель RU / EN ведёт на соответствующий URL того же сайта.

Из корня монорепозитория:

```sh
bun install
bun run --cwd apps/site dev
bun run --cwd apps/site typecheck
bun run --cwd apps/site lint
bun run --cwd apps/site build
```

Сайт по умолчанию запускается на `http://127.0.0.1:4176`. Сборка находится в `apps/site/dist`. Для размещения достаточно статического HTTP-сервера с HTTPS, обслуживающего `index.html`, `en/index.html` и `demo/index.html` по их адресам. API или Convex для сайта не требуются.

Публичный сайт размещён на `https://emailhost.olegsan.tech`. Сайт сохраняет mock-only demo и не обращается к почтовому backend. Собственный почтовый инстанс устанавливается отдельно, см. [подготовку публичной установки](../../docs/installation.md).

По умолчанию ссылка на исходники ведёт на `https://github.com/0legSan/email-host`. Перед сборкой можно передать `VITE_SOURCE_URL`, чтобы изменить публичный HTTP/HTTPS-адрес репозитория. Собственный код проекта использует MIT, сторонние компоненты сохраняют свои лицензии.

## Демо

`/demo/` использует настоящие `MailAppView`, mail controller, списки, reader, composer и настройки из `apps/web`. Его навигация находится в memory history и не меняет адрес сайта на production mail routes.

На главной странице встроено само приложение через `/demo/?embed=1`. Этот режим скрывает внешнюю шапку демо и открывает первое вымышленное письмо. CSS рекламной страницы не меняет интерфейс iframe. Его адаптивная компоновка, поиск, чтение, редактор и настройки остаются штатными. Подпись над окном сообщает о вымышленных данных, рядом доступна ссылка на полное демо.

По умолчанию встроенное демо находится в режиме просмотра. Iframe получает `inert` и не перехватывает прокрутку, касания или Tab. Кнопка «Управлять демо» включает настоящий ввод, выравнивает блок в окне и ограничивает его высоту экраном. Закреплённая панель сохраняет кнопку выхода. Необработанный приложением Escape также возвращает к сайту, в том числе из вложенного reader. Меню, настройки и редактор сначала обрабатывают Escape сами. Прокрутка страницы за пределы демо выключает управление без переноса фокуса. Переключение не перезагружает iframe и сохраняет открытое письмо, прокрутку и черновик. Полная страница `/demo/` сразу интерактивна.

Только сборка сайта подменяет границы:

- `@/lib/api-transport` возвращает локальные mock responses. Неизвестные API-запросы завершаются ошибкой, выхода к сети нет.
- `convex/react` заменяется demo adapter. Запросы пропускаются, mutation флагов изменяет локальные данные.
- `mail-storage-namespace` изолирует IndexedDB и ключи почтовых настроек. В настоящем приложении имена ключей и БД не меняются.
- PWA update и push adapters не регистрируют service worker и не запрашивают системные разрешения.

Вымышленные письма загружаются из памяти вкладки. Отправка добавляет письмо только в демонстрационную папку Sent. Подключение нового ящика не проверяет реальные реквизиты и не связывается с провайдером. Баннер на странице постоянно сообщает об имитации. Кнопка сброса очищает локальные demo mail caches и перезагружает страницу. Настройки темы и акцента сохраняются отдельно.

Основное приложение продолжает использовать обычный HTTP transport и настоящий Convex. Демо не является измерением производительности production IMAP/Convex.

## Языки приложения и примеров

Ссылки с русского сайта открывают `/demo/?lang=ru`, с английского `/demo/?lang=en`. Встроенное приложение получает тот же параметр. Переключатель в шапке полного демо и в настройках оформления меняет язык без перезагрузки. Явный `lang` имеет приоритет перед сохранённым `mail-language`, затем действует русский по умолчанию. Выбор синхронизируется между вкладками и iframe того же origin. Разные домены и порты не обмениваются им.

Все 300 исходных писем, имена отправителей, ящики, профили, подпись и имена вложений имеют RU/EN версии с одинаковыми ID. Смена языка обновляет неизменённые примеры, сохраняя флаги, перемещения и собственный ввод. Уже открытое исходное письмо и его цепочка обновляются вместе со списком, без повторного открытия. Уже вставленная подпись в открытом письме остаётся частью черновика. Сессия редактирования подписи сохраняет несохранённый текст, даже если переводится исходный seed-шаблон.

Блок о друзьях и близких описывает существующий механизм сервера. Владелец создаёт одноразовую ссылку регистрации со сроком действия, новый пользователь получает свой вход и подключает свои ящики. В демо реальные приглашения не создаются. Совместный доступ к чужим письмам этот сценарий не подразумевает.

## Оформление

Сайт и приложение используют `@workspace/mail-design`, общий `MailThemeProvider`, шесть accent presets, произвольный RGB HEX и `MailAppearanceSettings`. Тема хранится под ключом `theme`, акцент под `mail-accent`. Кэш почты, черновики, контакты и параметры почтового интерфейса демо используют префикс `email-host-demo:`. Это исключает чтение или сброс данных настоящего приложения даже на одном origin. Настройка локальна для браузера и origin. Разные домены не обмениваются ей.

Вложения из примеров доступны как локальные текстовые файлы. Прикрепление собственного файла в отправляемое письмо пока завершается объяснением ограничения демо. Реальные push, установка PWA и регистрация mailto в демо не выполняются.

Для произвольного цвета доступны нативная палитра и HEX-поле. Неверный ввод не меняет сохранённый цвет. Заливка сохраняет исходный HEX, контрастные foreground и text-role рассчитываются для выбранной темы. Свитч прочитанных и focus-outline используют общие роли. Ранний bootstrap и React provider применяют одинаковый валидатор.

Сайт сохраняет прямые углы приложения. Появление блоков, декоративный символ @ и движение по схемам отключаются через `prefers-reduced-motion`. IntersectionObserver снимает наблюдение после первого появления секции.
